

### ขั้นที่ 1 — พื้นฐาน 

ส่งมอบ: `package.json`, แอป Express, ค่าตั้งจาก `.env`, `docker-compose.yaml`,
Prisma schema ของทุกตาราง, migration แรก, ข้อมูลตั้งต้น (seed), health check,
หน้าข้อผิดพลาด, ตั้งค่า Jest

รายการตรวจ:
- [ ] `npm install`, `npm run db:migrate`, `npm run db:seed`, `npm run dev` ทำงานได้บนเครื่องใหม่
- [ ] `GET /healthz` ตอบ 200 และตอบ 503 เมื่อฐานข้อมูลหยุดทำงาน
- [ ] แอปไม่ยอมเริ่มทำงานเมื่อไม่มี `SESSION_SECRET` หรือสั้นเกินไป
- [ ] ฐานข้อมูลมีครบเก้าตาราง พร้อมข้อบังคับตามที่ระบุใน DESIGN.md
- [ ] URL ที่ไม่มีอยู่แสดงหน้า 404

### ขั้นที่ 2 — บัญชีผู้ใช้ 

ส่งมอบ: สมัครสมาชิก เข้าสู่ระบบ ออกจากระบบ session การป้องกัน CSRF
`requireLogin` และ `requireAdmin` หน้าโปรไฟล์ แก้ไขชื่อผู้ใช้ เปลี่ยนรหัสผ่าน สคริปต์สร้างผู้ดูแล

รายการตรวจ:
- [ ] รหัสผ่านในฐานข้อมูลเป็น bcrypt hash
- [ ] การสมัครสร้าง `member` เสมอ แม้คำขอจะส่ง `role=admin` มา
- [ ] คุกกี้ session เป็น `HttpOnly` และ `SameSite=Lax` และ ID เปลี่ยนเมื่อเข้าสู่ระบบ
- [ ] POST ที่ไม่มี CSRF token ถูกปฏิเสธด้วย 403
- [ ] อีเมลผิดและรหัสผ่านผิดได้ข้อความเดียวกัน
- [ ] เข้าสู่ระบบผิดหกครั้งติดกันถูกจำกัดด้วย 429
- [ ] สมาชิกที่เปิด URL ของผู้ดูแลได้ 403 ผู้เยี่ยมชมถูกพาไปหน้าเข้าสู่ระบบ
- [ ] เปลี่ยนรหัสผ่านต้องใส่รหัสผ่านเดิมให้ถูก และ session อื่นของบัญชีนั้นถูกยกเลิก

### ขั้นที่ 3 — รายการสถานที่ 

ส่งมอบ: หน้าแรก รายการสถานที่พร้อมการค้นหา ตัวกรองหมวดหมู่และ "เปิดอยู่ตอนนี้"
การเรียงลำดับ การแบ่งหน้า หน้าสถานที่พร้อมเวลาเปิดปิด เบอร์โทร ลิงก์ และปุ่มนำทาง
หน้าแผนที่ การสุ่มที่ไป API หมวดหมู่ migration เพิ่มคอลัมน์ `phone` และ `website_url`

รายการตรวจ:
- [ ] สถานที่ที่ยังไม่เผยแพร่ไม่ปรากฏในหน้าสาธารณะหรือผลลัพธ์ API ใด ๆ
- [ ] การค้นหา `%` หรือ `_` ไม่ได้ผลลัพธ์เป็นทุกรายการ
- [ ] "เปิดอยู่ตอนนี้" ถูกต้องสำหรับสถานที่ที่ปิดหลังเที่ยงคืน
- [ ] หน้า 0 หน้า 9999 และ `pageSize=1000` ถูกจัดการโดยไม่ขึ้นหน้าข้อผิดพลาด
- [ ] ใช้งานได้ที่ความกว้าง 375 px
- [ ] ปุ่มนำทางแสดงเฉพาะสถานที่ที่มีหมุด และเปิดแผนที่ที่ตำแหน่งถูกต้อง

### ขั้นที่ 4 — รีวิวและรายการโปรด

ส่งมอบ: เขียน แก้ไข และลบรีวิว คะแนนเฉลี่ยของสถานที่ บันทึกและลบรายการโปรด
หน้า "รีวิวของฉัน" และ "รายการโปรดของฉัน" ฟอร์มแจ้งข้อมูลผิดในหน้าสถานที่
(ตาราง `place_reports` ตัดออกเป็นอย่างแรกหากทำไม่ทัน)

รายการตรวจ:
- [ ] รีวิวที่สองของสถานที่เดิมโดยสมาชิกคนเดิมถูกปฏิเสธด้วย 409
- [ ] สมาชิกแก้ไขหรือลบรีวิวของคนอื่นไม่ได้ (403 หรือ 404)
- [ ] คะแนนเฉลี่ยและจำนวนรีวิวของสถานที่ถูกต้องหลังสร้าง แก้ไข และลบ
- [ ] บันทึกรายการโปรดเดิมซ้ำไม่สร้างสองแถวและไม่เกิดข้อผิดพลาด
- [ ] คะแนน 0, 6 และ 3.5 ถูกปฏิเสธ
- [ ] แจ้งข้อมูลผิดของสถานที่เดิมซ้ำขณะที่รายงานเดิมยังเปิดอยู่ไม่ได้ (409)

### ขั้นที่ 5 — การเสนอสถานที่และรูปภาพ

ส่งมอบ: ฟอร์มเสนอสถานที่พร้อมอัปโหลดรูปและแผนที่ปักหมุด หน้า "สถานที่ที่ฉันเสนอ" หน้ารายละเอียดพร้อมประวัติ
การแก้ไขและส่งใหม่ ตัวจัดเก็บรูปบนดิสก์ในเครื่อง

รายการตรวจ:
- [ ] รายการที่เสนอไม่ปรากฏในหน้าสาธารณะใด ๆ
- [ ] สมาชิกเปิดรายการที่สมาชิกคนอื่นเสนอไม่ได้
- [ ] ไฟล์ขนาด 6 MB, ไฟล์ `.exe` ที่เปลี่ยนชื่อเป็น `.jpg` และไฟล์ข้อความ ถูกปฏิเสธทั้งหมด
- [ ] รูปที่อัปโหลดถูกเก็บเป็น WebP ชื่อสุ่ม และไม่มีข้อมูล GPS
- [ ] รายการสถานะ `pending` แก้ไขไม่ได้ รายการที่ถูกส่งกลับแก้ไขได้
- [ ] ส่งรายการที่ไม่มีหมุด หรือหมุดอยู่นอกบริเวณลาดกระบัง ไม่ได้

### ขั้นที่ 6 — Admin

ส่งมอบ: คิวรายการที่เสนอ อนุมัติ / ส่งกลับ / ปฏิเสธ แก้ไขและยกเลิกการเผยแพร่สถานที่
ลำดับสถานที่แนะนำ ลบรีวิว จัดการหมวดหมู่ ปรับหมุดตอนตรวจ เพิ่มสถานที่โดยตรง รายการแจ้งข้อมูลผิด

รายการตรวจ:
- [ ] การอนุมัติสร้างสถานที่ที่เผยแพร่แล้วหนึ่งแห่งพอดี พร้อมแถวเวลาเปิดปิดเจ็ดแถว
- [ ] อนุมัติรายการเดียวกันสองครั้งพร้อมกันได้สถานที่เพียงแห่งเดียว ครั้งที่สองได้ 409
- [ ] หากสร้างสถานที่ล้มเหลว รายการที่เสนอยังคงเป็น `pending`
- [ ] การส่งกลับหรือปฏิเสธโดยไม่มีเหตุผลถูกปฏิเสธ
- [ ] ผู้เขียนกู้คืนหรือเขียนใหม่แทนรีวิวที่ผู้ดูแลลบไปแล้วไม่ได้
- [ ] หมวดหมู่ที่มีการใช้งานอยู่ลบไม่ได้ (409)
- [ ] ผู้ดูแลย้ายหมุดตอนอนุมัติ สถานที่ใช้ตำแหน่งใหม่ และประวัติบันทึกการย้าย
- [ ] ผู้ดูแลเพิ่มสถานที่โดยตรงได้ พร้อมแถวเวลาเปิดปิดเจ็ดแถว
- [ ] ผู้ดูแลปิดรายงานข้อมูลผิดได้ และรายงานที่ปิดแล้วไม่อยู่ในรายการรอตรวจ

### ขั้นที่ 7 — Security

ส่งมอบ: จำกัดอัตราคำขอ security header และ CSP, log แบบมีโครงสร้าง, ชุดทดสอบครบ,
GitHub Actions, Postman collection, ตรวจการเข้าถึงได้และการแสดงผลทุกขนาดจอ

รายการตรวจ:
- [ ] CI ผ่านบน pull request
- [ ] ไม่มีหน้าใดมีข้อผิดพลาด Content Security Policy ใน console ของเบราว์เซอร์
- [ ] ข้อผิดพลาดฝั่งเซิร์ฟเวอร์ที่บังคับให้เกิดแสดงหน้าทั่วไป และไม่เปิดเผย stack trace
- [ ] `npm audit --omit=dev` ไม่พบปัญหาระดับ high หรือ critical
- [ ] ทุกขั้นตอนใช้งานด้วยแป้นพิมพ์อย่างเดียวได้

### ขั้นที่ 8 — Deploy

ส่งมอบ: ฐานข้อมูลบนคลาวด์ ที่เก็บรูปบนคลาวด์ แอปที่ขึ้นระบบพร้อม HTTPS
บัญชีและข้อมูลสำหรับสาธิต สไลด์ฉบับสุดท้าย วิดีโอสาธิตสำรอง

รายการตรวจ:
- [ ] URL สาธารณะใช้งานได้บนมือถือผ่านเน็ตมือถือ
- [ ] ตั้ง `TRUST_PROXY=1` บนโฮสต์ และเข้าสู่ระบบได้จริงผ่าน HTTPS (ไม่ตั้งจะไม่มีคุกกี้ secure จึงเข้าสู่ระบบไม่ได้)
- [ ] รูปที่อัปโหลดบนระบบจริงยังแสดงอยู่หลัง redeploy
- [ ] สคริปต์สาธิตทั้งหมดรันได้ตั้งแต่ต้นจนจบ โดยไม่ต้องแก้ฐานข้อมูลด้วยมือ
- [ ] สมาชิกทุกคนตอบได้ว่า "ส่วนนี้ทำงานอย่างไร" สำหรับส่วนที่ตัวเองรับผิดชอบ
